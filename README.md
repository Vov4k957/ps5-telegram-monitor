# PS5 GitHub Monitor

Личный Telegram-бот: [@PS5monitorGH_bot](https://t.me/PS5monitorGH_bot).
Отслеживает GitHub Releases, включая Alpha, Beta и Pre-release. Черновики не отправляет.

## Управление в Telegram

- Отправь ссылку `https://github.com/owner/repo`, чтобы подписаться. Текущие релизы запоминаются без рассылки старых уведомлений.
- `/list` — подписки; `/remove` — удаление кнопками в одном сообщении.
- `/translate_on` и `/translate_off` — перевод changelog на русский.
- `/status` — после обновления Cloudflare Worker показывает последнюю фактическую проверку GitHub Actions (МСК), количество проверенных репозиториев, уведомлений, ошибок и предупреждение о задержке более 5 минут. Данные поступают в D1 после каждого запуска; без новых коммитов.
- `/check` — отчёт о проверке при очередном запуске; `/help` — справка.

Команды и кнопки доступны только владельцу в личном чате. Telegram-команды обрабатываются Cloudflare Worker через webhook практически сразу; GitHub Actions отвечает за мониторинг Releases. Подписки и настройка перевода хранятся в Cloudflare D1, история уже доставленных релизов — в `release_state.json`. Лимит — 30 подписок.

## Расписание и диагностика

- **Основной планировщик:** cron-job.org вызывает GitHub Actions `workflow_dispatch` примерно **раз в минуту**.
- **Резерв:** встроенный GitHub Actions `schedule` — `4-59/5 * * * *`, примерно каждые пять минут. Встроенное расписание может задерживаться или пропускать запуски.
- **Проверка фактической работы:** [GitHub Actions — PS5 releases to Telegram](https://github.com/Vov4k957/ps5-telegram-monitor/actions/workflows/ps5-telegram.yml). Открой последний запуск и вкладку **Summary** — она показывает фактическое время, число проверенных репозиториев, отправленных уведомлений и ошибок именно текущего запуска. Сводка также показывает период паузы при rate limiting.
- **Уведомления Telegram:** сообщения приходят только о новых опубликованных GitHub Releases, включая Alpha/Beta/Pre-release. Старые релизы не пересылаются при обычной проверке.

Важно: `last_run` и `last_heartbeat` в `release_state.json` **не означают последнюю успешную проверку**. Эти поля сохраняются только при изменении существенного состояния, чтобы не создавать до 1 440 лишних коммитов за сутки. Актуальную дату проверки смотри в **Actions → последний запуск → Summary**. Ответ Telegram `/status` подтверждает доступность Cloudflare Worker, но сам по себе не гарантирует, что GitHub Actions недавно запускался.

### Ограничения GitHub API

Монитор использует временный `GITHUB_TOKEN` из GitHub Actions и опрашивает Releases последовательно. При HTTP 500/502/503/504 или временном сбое соединения делает **не более одной быстрой повторной попытки**. При HTTP 403/429, означающем исчерпание лимита, соблюдает `Retry-After` или `X-RateLimit-Reset`; если явного срока нет, выдерживает не менее 60 секунд. Прекращает запросы к остальным репозиториям и сохраняет `github_backoff_until` в истории состояния, чтобы новый минутный запуск не возобновил обращения преждевременно. После окончания паузы монитор автоматически продолжит работу.

Релизы за период паузы будут обработаны при последующей успешной проверке, если они остаются в окне последних 30 GitHub Releases на репозиторий. При обычных проверках история не меняется — коммит не создаётся.

### Внешний планировщик

cron-job.org вызывает:

`POST https://api.github.com/repos/Vov4k957/ps5-telegram-monitor/actions/workflows/ps5-telegram.yml/dispatches`

с телом `{"ref":"main"}` и отдельным GitHub Fine-grained token, ограниченным **Actions: Read and write** только для этого репозитория. **Секреты не помещать в URL, код или сообщения Telegram.** Если токен истечёт, cron-job.org перестанет успешно запускать workflow; проверь его историю запросов и срок действия токена. Резервный GitHub `schedule` останется доступен с возможными задержками.

## Статус в Telegram через Cloudflare D1

После публикации Worker с поддержкой `POST /report`, `check_releases.py` автоматически передаёт туда итог каждого сканирования по защищённому каналу с существующим `SYNC_SECRET`. Worker сохраняет последнюю проверку в строку `settings.monitor_latest_run` Cloudflare D1 и отображает её по команде `/status`. Новую базу, таблицы или токены создавать не требуется. Новые GitHub Actions Secrets тоже не нужны.

При временной недоступности `/report` логируется предупреждение без остановки проверки релизов. В этом случае `/status` может показать устаревшую проверку и ссылку на GitHub Actions. Если Worker ещё не обновлён, новая функция Telegram пока не активна — до публикации Worker продолжит отправлять прежний ответ.

## Сохранность состояния

**Не удаляй `release_state.json`.** В нём находятся подписки, история release ID, настройки и Telegram offset. В Actions отсутствие или повреждение файла останавливает запуск без создания пустой истории.

Обработанные updates (если включён старый polling) и подтверждённые отправки сохраняются по мере выполнения. Сбой одного репозитория не мешает остальным, кроме глобального GitHub API rate limit, при котором монитор корректно приостанавливает запросы. ID отмечается доставленным только после успешного ответа Telegram; прежние ID не удаляются при выходе релиза из окна API. Workflow пытается сохранить прогресс даже после ошибки и берёт свежую `main` при запуске. При ошибке Git push сохраняет резервный артефакт на семь дней.

Абсолютное «ровно один раз» между Telegram и Git обеспечить нельзя: если Telegram принял сообщение, но ответ потерялся, либо состояние не удалось записать в Git, при повторе возможен дубль. Обычные повторные проверки и частичная ошибка после подтверждённых отправок не пересылают уже сохранённые релизы.

За одну проверку API получает до 30 последних опубликованных релизов на репозиторий. Долгий простой с большим числом новых релизов может потребовать отдельной сверки истории.

Перевод MyMemory работает без ключа; публичный changelog передаётся этому сервису. Ссылки, версии, код и известные технические термины защищены. При ошибке, исчерпании квоты или времени переводчика отправляется оригинал. Перевод не определяет, поддерживает ли релиз конкретную прошивку PS5.

## Проверки разработчика

`python3 -m unittest -q test_check_releases.py`

Тесты используют временные файлы и подменяют сетевые запросы. Проверяют команды и кнопки, добавление ссылкой, отсутствие старой рассылки, Alpha/Beta, перевод, сохранение истории после ошибок, отсутствие лишних коммитов, HTTP-ограничения GitHub и актуальные сводки Actions. Реальные подписки и Telegram при тестах не меняются.
